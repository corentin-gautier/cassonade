# Cassonade

Fabric mod for Minecraft 26.3 (Java 25, Gradle, Fabric API). The [README](README.md) (English, for players) describes every feature and is the reference for expected behavior. Internals, textures, recipes, tests and releases are in [CONTRIBUTING.md](CONTRIBUTING.md): before exploring the code for a feature, search for its heading under "How the features work" (it names the classes and mixins involved) rather than reading the whole file.

## Mod Philosophy

The mod fixes small annoyances and brings the world to life without changing how the game is played. Before adding anything:

- No new ores, equipment tiers, magic, machines, monsters, biomes or dimensions. Nothing that makes the game easier to complete, only more pleasant to play.
- A tool is unlocked by equipping a vanilla item (compass, clock) or an item crafted from vanilla items (backpack, world map). Vanilla progression must not change.
- Ambience (birds, sounds, sky) is always there: it gives no advantage, so no item unlocks it, and for now no setting turns it off.
- The interface keeps Minecraft's pixel style and sounds, following the art direction (sepia wood, dark slots, leather, cream-colored paper).
- One consistent interface, no configurable options, no extra screens: every feature works one way, as close to vanilla as possible.
- The client must stay usable on a server without the mod: features that need the server fall back to vanilla behavior.

## Commands

- `./gradlew build`: jar in `build/libs/`.
- `./gradlew runClient`: launches the game (user `Corentin`, offline, worlds in `run/`).
- In `runClient`, `/dev kit`, `/dev unequip`, `/dev goto biome|structure <id>`, `/dev goto town`, `/dev goto tavern [plains|desert|savanna|snowy|taiga]`, `/dev edit <template>|all` (a tavern built to change by hand, its structure block saving it into `src/main/resources`), `/dev lights` (every light side by side in a hall), `/dev regen` (terrain made again at the next opening) and `/ambience <effect>` set up a feature to try in seconds, from `F6` to `F10` too, and `F12` shows the game's own rendering to compare (see CONTRIBUTING.md); they exist only in the development environment.
- `./gradlew runClientGameTest`: end-to-end tests in the real client; 1920×1080 screenshots in `build/run/clientGameTest/screenshots/`. Run it after changing behavior or the interface, with `-Ptests=Gear,Quest` to run only the relevant tests (class name without `ClientGameTest`, see `src/gametest`). While developing a feature, prefer a small dedicated test (such as `Clock`), and split a test that grows to cover several features. Other flags (`-PexploredWorld`, `-Pprofile`, `-PsiteScreenshots`, `-PsiteIcons`) are in CONTRIBUTING.md.

## Organization

- `src/main`: shared client and server code. Each feature has its own package (`gear`, `compass`, `hopper`, `combat`…) registered by an `init()` called from `Cassonade`.
- `src/client`: rendering and screens; entry point `CassonadeClient`.
- `src/gametest`: client tests.
- `src/textures`: the two texture atlases, cut into the game's files by Gradle.
- `promo/`: everything that presents the mod: `site` (the website), `store` (Modrinth and CurseForge pages), `video` (trailers and thumbnails, not in git).
- `tools/`: the texture, recipe and store scripts.
- Mixins are declared in `cassonade.mixins.json` (main) and `cassonade.client.mixins.json` (client), mostly named after the vanilla class they patch (`AnvilMenuMixin`): search by that class to see what already changes it.
- `src/main/resources/data/minecraft/recipe` is generated by `tools/rebalance_recipes.py`: never edit it by hand.
- All displayed text goes through language files: update `en_us.json` and `fr_fr.json` together.

## File names

Lowercase kebab-case (`convert-screenshots.sh`, `overview-1.12-1440p.mp4`), unless a tool or the language decides otherwise: Java classes (PascalCase), Python modules and Minecraft resources, including the site's item icons named after them (snake_case), Jekyll's `_` folders, standard files (`README.md`, `FUNDING.yml`). The site's page names are public URLs: leave them as they are.

## Textures

- **Never run `tools/build_gui.py`**: it redraws `src/textures/gui.png` and erases manual edits.
- Interface textures live in the `src/textures/gui.png` atlas (layout in `src/textures/gui.json`), split by Gradle at build time. To add one, place it under `src/main/resources/assets/…` and run `python3 tools/gui_atlas.py`.
- All other textures (blocks, items, the spyglass view, the icon) live in the `src/textures/world.png` atlas (layout in `src/textures/world.json`), split the same way. To add one, place it under `src/main/resources/assets/…` and run `python3 tools/world_atlas.py`.
- Textures can be drawn by dependency-free Python scripts (`tools/*_textures.py`, `tools/icon_texture.py`, using `tools/pngio.py`), with colors from `tools/gui_theme.py`; their PNGs are then packed into the atlas, replacing any hand edit of those textures.

## Documentation

A change to player-visible behavior updates, in the same commit:

- the [README](README.md) (feature section and tables);
- [CONTRIBUTING.md](CONTRIBUTING.md), if documented internals change;
- the site, if it covers the feature: both [promo/site/_data/en.yml](promo/site/_data/en.yml) and [promo/site/_data/fr.yml](promo/site/_data/fr.yml) (home section, and the feature's `detail` with FAQ; files in `promo/site/features/` and `promo/site/fr/fonctionnalites/` hold only title and description). If the site doesn't cover the feature yet, ask whether to add it.
- The stores [description](promo/store/description.md)

Never edit [CHANGELOG.md](CHANGELOG.md): git-cliff generates it at release time.

## Commits and Versions

- English [Conventional Commits](https://www.conventionalcommits.org/): `feat(<feature>): <player benefit>`, `fix(<feature>): <what is fixed>`. Only `feat`, `fix` and `perf` reach the changelog; `refactor`, `docs`, `chore`, `ci`, `build` and `test` do not.
- Scope is the affected feature, named as the site and README name it, since it shows in the changelog: `backpack`, `inventory`, `hopper`, `minimap`, `world-map`, `clock`, `waystone`, `spyglass`, `elytra`, `quests`, `combat` (health bar, awareness, weapons, poison), `sculk-torch`, `harvest`, `woodcutter`, `recipes`, `lights` (colored lights, light in hand, sky), `sea` (the sea, under water, the diving mask), `ambience` (the living world: animals, weather, particles, sounds), `villages` (towns, taverns, village houses), `structures` (mansions, temples, loot, worldgen), `interface`, and `tweaks` only for a small detail that belongs to none of them. Site changes use `docs(site): …`.
- Describe the player-facing result, not the implementation: `feat(hopper): give every hopper a filter slot`.
- The version in `gradle.properties` is changed only by the manually launched Release workflow (Actions tab). Do not edit it or create tags by hand.
