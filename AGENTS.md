# Cassonade

Fabric mod for Minecraft 26.3 (Java 25, Gradle, Fabric API). The [README](README.md) (English, for players) describes every feature and is the reference for expected behavior. Internals, textures, recipes, tests and releases are in [CONTRIBUTING.md](CONTRIBUTING.md): before exploring the code for a feature, search for its heading under "How the features work" (it names the classes and mixins involved) rather than reading the whole file.

## Mod Philosophy

The mod fixes small annoyances without changing how the game is played. Before adding anything:

- No new ores, equipment tiers, magic, machines, monsters, biomes or dimensions. Nothing that makes the game easier to complete, only more pleasant to play.
- A feature is unlocked by equipping a vanilla item (compass, clock) or an item crafted from vanilla items (backpack, world map). Vanilla progression must not change.
- The interface keeps Minecraft's pixel style and sounds, following the art direction (sepia wood, dark slots, leather, cream-colored paper).
- One consistent interface, no configurable options, no extra screens: every feature works one way, as close to vanilla as possible.
- The client must stay usable on a server without the mod: features that need the server fall back to vanilla behavior.

## Commands

- `./gradlew build`: jar in `build/libs/`.
- `./gradlew runClient`: launches the game (user `Corentin`, offline, worlds in `run/`).
- `./gradlew runClientGameTest`: end-to-end tests in the real client; 1920×1080 screenshots in `build/run/clientGameTest/screenshots/`. Run it after changing behavior or the interface, with `-Ptests=Gear,Quest` to run only the relevant tests (class name without `ClientGameTest`, see `src/gametest`). While developing a feature, prefer a small dedicated test (such as `Clock`), and split a test that grows to cover several features. Other flags (`-PexploredWorld`, `-Pprofile`, `-PsiteScreenshots`) are in CONTRIBUTING.md.

## Organization

- `src/main`: shared client and server code. Each feature has its own package (`gear`, `compass`, `hopper`, `combat`…) registered by an `init()` called from `Cassonade`.
- `src/client`: rendering and screens; entry point `CassonadeClient`.
- `src/gametest`: client tests.
- Mixins are declared in `cassonade.mixins.json` (main) and `cassonade.client.mixins.json` (client), mostly named after the vanilla class they patch (`AnvilMenuMixin`): search by that class to see what already changes it.
- `src/main/resources/data/minecraft/recipe` is generated by `tools/rebalance_recipes.py`: never edit it by hand.
- All displayed text goes through language files: update `en_us.json` and `fr_fr.json` together.

## Textures

- **Never run `tools/build_gui.py`**: it redraws `textures/gui.png` and erases manual edits.
- Interface textures live in the `textures/gui.png` atlas (layout in `textures/gui.json`), split by Gradle at build time. To add one, place it under `src/main/resources/assets/…` and run `python3 tools/gui_atlas.py`.
- All other textures (blocks, items, the spyglass view, the icon) live in the `textures/world.png` atlas (layout in `textures/world.json`), split the same way. To add one, place it under `src/main/resources/assets/…` and run `python3 tools/world_atlas.py`.
- Textures can be drawn by dependency-free Python scripts (`tools/*_textures.py`, `tools/icon_texture.py`, using `tools/pngio.py`), with colors from `tools/gui_theme.py`; their PNGs are then packed into the atlas, replacing any hand edit of those textures.

## Documentation

A change to player-visible behavior updates, in the same commit:

- the [README](README.md) (feature section and tables);
- [CONTRIBUTING.md](CONTRIBUTING.md), if documented internals change;
- the site, if it covers the feature: both [site/_data/en.yml](site/_data/en.yml) and [site/_data/fr.yml](site/_data/fr.yml) (home section, and the feature's `detail` with FAQ; files in `site/features/` and `site/fr/fonctionnalites/` hold only title and description). If the site doesn't cover the feature yet, ask whether to add it.

Never edit [CHANGELOG.md](CHANGELOG.md): git-cliff generates it at release time.

## Commits and Versions

- English [Conventional Commits](https://www.conventionalcommits.org/): `feat(<feature>): <player benefit>`, `fix(<feature>): <what is fixed>`. Only `feat`, `fix` and `perf` reach the changelog; `refactor`, `docs`, `chore`, `ci`, `build` and `test` do not.
- Scope is the affected feature: `backpack`, `compass`, `world-map`, `clock`, `inventory`, `farming`, `elytra`, `hopper`, `quests`, `combat`, `spyglass`, `recipes`, `tweaks`, `ambience`, `interface`. Site changes use `docs(site): …`.
- Describe the player-facing result, not the implementation: `feat(hopper): give every hopper a filter slot`.
- The version in `gradle.properties` is changed only by the manually launched Release workflow (Actions tab). Do not edit it or create tags by hand.
