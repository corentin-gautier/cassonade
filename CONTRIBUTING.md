# Contributing to Cassonade

Thanks for wanting to help. This file covers everything that is not about playing: building and testing the mod, how each feature works under the hood, the texture pipeline, translations, commits and releases. What the mod does for players is in the [README](README.md), which is also the reference for the expected behavior.

## The spirit of the mod

Before adding anything, check it fits:

- No new ores, gear tiers, magic, machines, mobs, biomes or dimensions. Nothing that makes the game easier to beat, only nicer to play.
- A new feature is unlocked by equipping a vanilla item (compass, clock) or one crafted from vanilla items (backpack, world map). Vanilla progression does not change.
- The interface keeps Minecraft's pixel style and sounds, in the mod's art direction (sepia wood, dark slots, leather, cream paper).
- On a server without the mod, the client must stay usable: features that need the server fall back to vanilla behavior.

## Getting started

The project needs Java 25. Gradle downloads it automatically for this project (see `gradle/gradle-daemon-jvm.properties`): there is nothing to install.

- `./gradlew runClient`: launches the game with the mod (username `Corentin`, offline, worlds in `run/`).
- `./gradlew build`: builds the jar in `build/libs/`.
- `./gradlew runClientGameTest`: the end-to-end test in the real client (see [Tests](#tests)).

Without a terminal, there are two other ways to launch the game with the mod:

- **From the Finder**: double-click `Lancer le jeu.command`. On first launch, macOS may refuse to open the file: then right-click → Open → Open.
- **From VS Code**: `Cmd+Shift+B`. The other actions (automated tests, building the jar) are under `Cmd+Shift+P` → "Tasks: Run Task".

The game opens offline: no Microsoft account needed, but online multiplayer is not available. Test worlds are saved in `run/` and come back at each launch. The first launch takes a few minutes (downloading Java 25 and Minecraft), the next ones about 30 seconds.

## Project layout

- `src/main`: shared by client and server (items, slots, recipes, network payloads, server mixins). One package per feature (`gear`, `compass`, `hopper`, `combat`…), each registered by an `init()` called from `Cassonade`.
- `src/client`: rendering and screens (HUD, minimap, map, journal), entry point `CassonadeClient`.
- `src/gametest`: automated client tests.
- Mixins are declared in `cassonade.mixins.json` (main) and `cassonade.client.mixins.json` (client).
- `src/main/resources/data/minecraft/recipe`: rebalanced recipes, generated by `tools/rebalance_recipes.py`, never edited by hand.
- `tools/`: Python scripts, without dependencies, that draw the textures and generate the recipes.

Code style: tabs for indentation, comments in English that explain the why, at the density of the surrounding code. Follow the style of the file you are editing rather than introducing new patterns.

## Tests

`./gradlew runClientGameTest` launches the game in automated test mode (`src/gametest`). It creates a world, equips the backpack, the compass and the world map, explores and opens the world map, places a named marker then removes it, changes the marker display, opens and closes the backpack with `B`, checks hand refill, bulk crafting and map previews, takes pictures of the restyled windows, sets a hopper's filter, checks saving and death, then closes the game. Other test classes join a dedicated server with the mod and Minecraft's own server without it.

- `-Ptests=Gear,Quest` runs only those tests (the class name without `ClientGameTest`: `Gear`, `WorldMap`, `Storage`, `Hopper`, `Everyday`, `Screens`, `Quest`, `Interface`, `Clock`, `Tweaks`, `ArmorStand`, `Lights`, `Anvil`, `Bookshelf`, `Cauldron`, `Woodcutter`, `Loom`, `FlowerPot`, `VehicleExit`, `SignEdit`, `BookEdit`, `FacingPreview`, `OrganizedBackpack`, `Combat`, `Markers`, `Inventory`, `Search`, `Tooltips`, `Workstations`, `InfoPanels`, `WorldSelection`, `Spyglass`, `Glance`, `DedicatedServer`, `VanillaServer`). `-Ptests=InfoPanels` opens every GUI that uses an info icon and saves a screenshot for each. Run the tests your change touches; while working on a feature, a small test of its own (like `Clock`) runs much faster; give a new feature its own test rather than growing an existing one.
- Screenshots, in 1920×1080, are in `build/run/clientGameTest/screenshots/`.
- `-PsiteScreenshots` retakes the website's screenshots as PNG (the world they are taken in, its map already explored, is kept in `build/site-world` from one run to the next, and made again when the seed, the game's version, the route or the map's drawing change; delete the folder to make it again), which [tools/convert_screenshots.sh](tools/convert_screenshots.sh) turns into the site's AVIF and the stores' JPG (the VS Code task "Prendre les captures d'écran" runs both; see [site/assets/screenshots/README.md](site/assets/screenshots/README.md)).

Run them after any change to behavior or interface.

## Code quality audit plan

Review the codebase in bounded passes so each finding can be checked against the code and its tests:

1. **Map the codebase:** list source sets, feature packages, entry points, shared helpers, mixins, generated files and existing tests.
2. **Review shared foundations:** inspect registration and lifecycle, networking and persistence, common utilities, and server-side mixins for correctness, coupling and error handling.
3. **Review feature families:** inspect client features and screens in small groups, checking ownership, state lifetime, duplicated logic, complexity and whether behavior is covered by game tests.
4. **Review tooling and tests:** assess build configuration, texture/recipe generators and test coverage; verify generated files are not treated as hand-maintained sources.
5. **Validate and report:** run focused tests for confirmed issues, then the build; report only reproducible, actionable findings with severity, file/line references, suggested fixes and explicit coverage limits.

Keep the audit read-only until findings are prioritized. Fix confirmed issues in separate, focused changes, adding regression tests where practical; track unreviewed areas between passes so the final report distinguishes full coverage from sampling.

## How the features work

### Equipment slots

Instruments that show something on screen sit in the column above the offhand: compass, world map, clock. What is worn on the body follows the offhand along the bottom row: elytra, then backpack. Equipment is stored in a player attachment (`PlayerGear`). An item crafted from a slot's vanilla item goes in the same slot and unlocks more: the barometer (clock and lightning rod) in the clock's, the sculk compass (compass and sculk sensor) in the compass's. Their textures, and the website's copies in `site/assets/items`, are generated from the game's textures by `tools/gear_item_textures.py`, as are the naturalist's spyglass's (spyglass, book and sculk sensor), which is held, not worn.

- Shift-click equips these items. With the backpack open, other items go into it (armor and shields keep their vanilla priority); closed, Shift-click stays vanilla. Picked-up items always go to the inventory.
- The inventory tabs open the recipe book (in place of the vanilla button), the backpack and, with a world map equipped, the world map. The open book also closes with its bookmark ribbon, the backpack with the strap of its flap.
- The backpack's contents live in the item (`DataComponents.CONTAINER`), like a Shulker box.
- The organized backpack (`gear/OrganizedBackpack`) is a `BackpackItem` of its own, made by a `smithing_transform` that copies the contents. Its template is added to chests through `LootTableEvents.MODIFY`. `HandRefill` falls back on it, `InventoryMixin` counts it for the recipe book on both sides, `ServerPlaceRecipeMixin` takes ingredients from it, `ItemEntityMixin` tops up its partial stacks on pickup.
- In Creative mode, the slots are not shown. On a server without the mod, which has nowhere to keep them, the slots, the backpack and the sort buttons are not offered.

### Loading screen

`WorldLoading` draws a world's first load, in singleplayer or joining a server, on the map of what was explored: in sepia (`RegionOverviews`), each loaded chunk coming into color; land never seen is hatched, then inked. In singleplayer the chunks come from the server's own view and the center from `LevelLoadTracker.updateFocus`; a server tells nothing, so the bar counts the chunks arrived around the player. The steps before (`GenericMessageScreen` by its translation key, `ConnectScreen`) use the same layout with blank paper, as does the one frame of `ProgressScreen` the game shows between them (`WorldLoading.between`). A portal or any later change of dimension has no chunk view and follows no connection, so it stays vanilla. Saving on leaving (`menu.savingLevel`) shows the world's name over a floppy disk, drawn by `tools/loading_textures.py`: the game tells nothing of its progress. `-PexploredWorld` takes the screenshots.

### Compass and world map

- Minimap zoom, rotation and marker display are kept in `config/cassonade.properties`.
- The world map item is the only one the map slot accepts. Its texture, a filled map in a frame of sticks, is generated from the game's textures by `tools/world_map_texture.py`.
- Exploration is recorded at all times, even without a world map: chunks within 6 chunks of the player count as explored. The data stays on the client, in the world folder in singleplayer (`cassonade/worldmap`), in `cassonade/worldmap/servers/<address>` in the game folder in multiplayer.
- From 1/4 zoom out, the world map draws each region as a 128 × 128 overview (`RegionOverviews`), read on a background thread and kept for the session, redone from the loaded region when its colors change, a few textures made per frame: a whole explored world can then show without loading its regions in full. Regions are evicted from their cache between frames only, never while the map is open, since a texture released after being queued for drawing would have its id reused by another.
- Each region also saves the surface biome in 4 × 4 block cells, so holding `Shift` while hovering an explored area names its biome even after its chunk unloads (`TerrainColors`, `MapRegion`).
- Markers are saved on the player (64 at most, across all dimensions) and kept on death. They are drawn as the vanilla map banners, each texture pixel a whole number of screen pixels so they stay sharp at any size (`MapDecorations.banner`). In the world, the banner and its label (in whole screen pixels per font pixel) shrink from 16 to 256 blocks away.
- The death marker is the game's own last death location, which it sends the client for the recovery compass: nothing from the server, it works anywhere. Once the player has gone more than 12 blocks away, coming back within 4 puts it away; that choice is kept next to the explored map (`dismissed_death.json`). Its icon is the treasure map's red X.
- The spawn chunk is the chunk of the world's spawn point, which the game sends every client: outlined in the paper color over a dark line, never under 6 GUI pixels wide, named on hover. Client only.
- Lodestones come from the `lodestone_tracker` of every compass carried (inventory, offhand, the compass's gear slot), in the current dimension, one marker per lodestone (`LodestoneMarkers`). Their icon is the vanilla map's white X (`target_x`). Client only.
- Coordinates in chat messages (three whole numbers, perhaps labelled x, y, z, a height of four digits at most) become links while the world map is worn and the server has the mod (`ChatCoordinates`). The link is a custom click event that `ScreenMixin` keeps on the client, opening the world map there with its name box.
- Minecraft saves keys by their position on a QWERTY keyboard; `M`, `B`, `N`, `+` and `-` follow the character printed on the player's keyboard instead. If the matching key is already taken, the zoom picks another: on a Mac AZERTY keyboard `+` is the command key, so zooming in moves to `)`; on a PC AZERTY keyboard `-` is hotbar slot 6, so zooming out moves to the numpad `-`.

### Clock

The forecast comes from the server every second to the players wearing a barometer, read from its weather timers. It is not shown on a server without the mod, nor when the weather is frozen (`advance_weather` set to `false`). When a thunderstorm could start or stop before the next rain change, the game rolls for it later: the forecast then simply says rain. The weather icons, the moon's phases and the bed are in the interface atlas, drawn by `tools/gui_textures.py`. The moon's phase is the game's own (the `visual/moon_phase` environment attribute), shown where there is weather, so in the overworld. When a bed would let the player sleep, the chime rings and the moon blinks with the bed for 5 seconds, half a second each, in the moon's place so the panel keeps its width, on the client: at nightfall or as a thunderstorm starts, not when joining at night.

### Storage

- Sorting merges identical stacks then orders them by item. It touches the 27 inventory slots, never the hotbar or armor; stashing does not take from the hotbar either, and needs the chest open.
- Shift-drag moves each hovered stack as if it were Shift-clicked, until Shift or the button is released. In the Creative inventory, Shift-click keeps its usual behavior.
- Scrolling down over a stack takes it, puts one item back, Shift-clicks that item, then puts the rest back: vanilla clicks only, so it works on any server, and the item lands where the menu's own Shift-click sends it. Scrolling up does nothing, and a bundle keeps the wheel for choosing its item. Not in the Creative inventory, nor on a locked slot. Trackpad scrolling adds up to a full notch per item.
- Locked slots are kept on the player by the server (one bit per inventory slot, hotbar included), kept on death and synced to its own client. The server skips them when sorting and stashing, and a Shift-click does not fill them when empty (it still tops up their stack); the client does not send a Shift-click from them, nor the drop key, in a window or on the selected hotbar slot (`MultiPlayerGameModeMixin`). Hand refill ignores them, to keep refilling a locked hotbar slot. A left click with the lock key held (`Alt` by default) toggles a slot; screens do not update key mappings, so the client checks the bound key itself. It works in every container window but the Creative inventory, and not on a server without the mod. The padlock is in the interface atlas.
- Inventory sounds are the bundle sounds, at different pitches depending on the gesture.
- Container previews show nine slots per row, three rows at most with the count of the other items in the last slot, and an amber fill bar. Tooltips have 6 pixels of inner padding instead of 3. An unopened loot Shulker box keeps the game's "???".
- The server only sends a map's contents when it is in the player's inventory: a map never carried keeps the vanilla tooltip.
- With food in hand that the player could eat (main hand first, as the use key), the drumsticks it would restore blink on the hunger bar, the game's own sprites faded in and out (`HudFoodPreviewMixin`). Client only.
- Food tooltips draw two named lines of the hunger bar's own drumstick sprites, two points to a drumstick: the hunger restored, then the saturation, the same sprites tinted gold, its points rounded up. Client only.
- Enchantment descriptions are in the language files, `gui.cassonade.enchantment.<namespace>.<path>`; an enchantment without one (from a data pack or another mod) shows its name alone. They are wrapped at 180 pixels. Client only: it works on any server.
- The anvil penalty is the item's own `repair_cost`, which the game adds to every anvil use and doubles, plus one, each time. Shown from 1 level, as the tooltip's last line. Client only.
- An anvil rename with no repair or enchantment operation costs no levels (`AnvilMenuMixin`); repair and enchantment operations keep their vanilla cost.
- Fuel burn times are data-driven providers in a loot context only the server can build: it reads them as a furnace would and sends them on joining and after a data pack reload (`furnace/FuelTimes`). A blast furnace or smoker burns twice as fast and cooks twice as fast, so a furnace's 200 ticks per item gives the count for all three. The line shows only in their windows; on a server without the mod, not at all.
- A brewing stand's own menu syncs the remaining brew time and fuelled batches to every client. `BrewingStandScreenMixin` shows those values without a server payload; the active batch is included in the remaining count.
- Storage search is client-only. `ContainerSearch` opens a field above the window, framed like a small window (`tools/search_field_texture.py` cuts it from the inventory's edge), from the small `F` button or Ctrl/Cmd+F, and dims non-matching storage slots without hiding them. It searches names, item IDs, enchantment names and IDs, and nested bundle or Shulker box contents.
- The list of items picked up comes from the packet the server sends every client when a player picks something up, vanilla or not, read before the game takes the amount off the item on the ground. Arrows and tridents are left out (they are not item entities). Client only.
- Hand refill prefers an identical stack (same enchantments, same wear) and only searches the inventory, then an organized backpack, never the plain one. Dropping or moving a stack does not trigger it.
- Bulk crafting leaves what does not fit in a full inventory in the grid.
- The durability warning only watches enchanted items in hand and in the armor slots, and only as they wear: the client compares each slot with the tick before, so an item already worn when taken in hand stays quiet (switching hotbar slots counts as taking another item). It warns at 5 % of the durability, at least 10 uses, then at 3 uses, without telling how many are left. Client only: it works on any server.

### Small tweaks

- **Chiseled bookshelves**: at arm's length or through the naturalist's spyglass, the book in the aimed-at slot shows its display name. The bookshelf syncs its contents to the client (`ChiseledBookshelfSyncMixin`); on a server without the mod, titles stay hidden.
- **Boats** climb steps of two pixels at most, left by blocks slightly lower than a full block (dirt path, farmland, soul sand, mud, carpets, thin snow).
- **Enchanting table**: the client computes every enchantment like the server, from the enchantment seed the server sends in full (the game only sends 16 bits of it, which is not enough). On a server without the mod, the tooltip stays vanilla.
- **Leaves** placed by a player never disappear; the others drop their saplings, sticks and apples as usual.
- **Facing preview** (`client/FacingPreview`): client only, it asks the held block's `getStateForPlacement` with the crosshair's hit and draws a small dark pixel cross and four corners on that face of the block to come as gizmos each tick.
- **Book editing** (`client/mixin/BookEditScreenMixin`): client only, `+` and `-` change the screen's page list, sent as usual on "Done".
- **Sign editing** (`client/mixin/AbstractSignEditScreenMixin`): client only, it maps the mouse to a line and a cursor position through the screen's text scale and offset, and a multi-line clipboard replaces the four lines.
- **Getting off** (`tweaks/VehicleExit`): `AbstractBoatMixin` and `AbstractMinecartMixin` replace a player's dismount location by the first free spot around the vehicle, trying the eight sides from the one looked at, then falling back to vanilla (open water, no room).
- **Trees** (`tweaks/TreeClearance`): `TrunkPlacer.getTreeHeight` is raised by 2, except one tree in eight that stays vanilla, so the canopy sits above a player's head. Leaves are still refused below the sapling's `y + 2`, for hanging cherry and pale oak. Bushes (`BushFoliagePlacer`) and leaves the player places are left alone. Server side; on a server without the mod, trees stay vanilla.
- **Signs on chests**: a wall sign hung on a chest, trapped chest or barrel passes the click on to it, on the server. Sneaking still edits the sign, items applied to signs (dyes, glow ink, honeycomb) still apply, and a sign with click commands runs them.
- **Item frames on chests**: a frame holding an item, hung on a chest, trapped chest or barrel, passes the click on to it, on the server (`ItemFrameMixin`). Sneaking turns the item, an empty frame still takes the item in hand, and shears still hide the frame.
- **Double doors** only pair wooden doors of the same wood, same facing and opposite hinges.
- **Composter**: a hopper underneath takes all 8 bone meal at once, as soon as it has room for them.
- **Daytime**: from day tick 0 to 12000, the overworld clock runs at half its rate (`time/LongDay`). Only the rate the server ticks with and sends to clients changes, not the saved one: `/time rate` keeps working, and removing the mod restores the vanilla pace. Each change is sent with the vanilla time packet, so a vanilla client sees the sun slow down too. Phantoms count the time since the last rest in 36000-tick days, so they still come after three sleepless nights, and the weather forecast places the next change on the slower day.
- **Villagers** on a lead: wandering traders still cannot be leashed.
- **Damage direction** (`combat/DamageDirection`): the client already receives, with each damage event, where the hit came from (the attacker, the projectile or the explosion). The arc is drawn pixel by pixel on the GUI grid, on a circle around the crosshair at 30 % of the screen's height, and follows the player's turning for its 30 ticks. Hits without a place (falls, hunger, fire) show nothing. Client only: it works on any server.
- **Attacking through plants** (`combat/ThroughPlants`): when the attack key is pressed on a block with no collision that breaks at a touch (grass, flowers, crops, saplings, torches…), the client looks for a mob behind it within the attack's reach, with no block with collision in between, and attacks it instead. Only the attack: the crosshair and the use key still pick the plant. The server only checks the attack's range, so it works on any server.
- **Dynamic lights** (`light/DynamicLights`): each tick, the client lists the entities within 64 blocks of the camera that carry light (a light block or a lava bucket in either hand, a dropped one, or burning), at most the 32 nearest, at their eye's block. Their light fades by one per block of straight-line distance, through walls. It is added where the game reads light to draw: `LightCoordsUtil.getLightCoords` (chunk meshes, block entities, paintings) and `EntityRenderer.getBlockLightLevel` (entities, hands). When a light moves to another block, the sections it reaches are rebuilt. The world's light does not change, so spawning stays vanilla. Client only: it works on any server.
- **Item frames** (`ItemFrameMixin`): shears toggle the frame's vanilla `Invisible` flag, only on a frame holding an item, and wear by one use. A hidden frame whose item is knocked out shows again, so an empty frame is never left invisible on the wall. Server side: on a server without the mod, shears go in the frame as in vanilla.
- **Ladders**: a ladder used on a ladder extends the column of ladders with the same facing at its far end, upward, or downward when the player looks down (sneaking would skip the block's use for the item's). It stops at a taken spot or where the wall ends, and falls back to vanilla placing. Server side (`LadderBlockMixin`): on a server without the mod, placing stays vanilla.
- **Sculk torch** (`light/SpawnSpots`): twice a second, the client looks 12 blocks around and 8 up and down for spots where a zombie could spawn (`isValidSpawn` on the block below, `NaturalSpawner.isValidEmptySpawnBlock` for the two above) with no more block light than the dimension allows; a sky light above 7 makes it a night-only spot. Each spot gets the creeper's face, 8 by 8, as flat translucent gizmo squares on its ground, dark for any time, light for night only, redrawn every tick. Its texture is drawn by `tools/gear_item_textures.py`. Client only.
- **Farmland**: a fall on farmland no longer turns it to dirt when the one falling is a player, or a mount a player rides (`FarmlandBlockMixin`). Mobs still trample it, under the `mobGriefing` rule. Server side.
- **Furnace experience**: the server sends the player with a furnace open `FurnaceExperience` (the sum of `recipesUsed` times each recipe's experience, in tenths, read through `AbstractFurnaceBlockEntityAccessor` so no orbs are given out), checked every 10 ticks; `AbstractFurnaceScreenMixin` adds it to the small line showing the furnace's times and fuel, nothing on a server without the mod.
- **Furnaces**: the flame and the arrow are vanilla's sprites with their gray background made transparent by [tools/furnace_progress_textures.py](tools/furnace_progress_textures.py), over the window's own unlit flame and empty arrow; the blast furnace and the smoker use the furnace's. The brewing stand's bubbles and arrow ([tools/brewing_progress_textures.py](tools/brewing_progress_textures.py)) are vanilla's too, with the gray background made transparent and the furnace's yellow and orange. In `AbstractFurnaceScreenMixin`, the time left is the items to cook times the cooking time, minus the time spent, from the timers the window syncs; the fuel's count adds the burning fuel's time left, in cooking times, to the waiting fuel's items (FuelTimes). Both, with the held experience, share one panel next to the window (`InfoPanel`). Client only; on a server without the mod, the waiting fuel does not count.
- **Grindstone**: the client adds up the enchantments' worth as `GrindstoneMenu` does (curses aside) and shows the range the game draws from, half of it rounded up to twice that minus one, where the anvil shows its cost (`GrindstoneScreenMixin`). Client only.
- **Sweeping**: a sweep counts the animals the player owns (`OwnableEntity`: wolves, cats, parrots, horses…) as allies, like teammates, and leaves them alone (`PlayerMixin`). Server side.
- **Chat mentions**: a chat message from anyone but the player whose text has their name as a word of its own, in any case, rings a note block bell (`ChatMentions`). Fabric's chat event fires just before the message is added to the chat, where `ChatComponentMixin` rebuilds it piece by piece, styles kept, the name in gold. Client only.
- **Armor stands**: `Alt` (the slot lock's key, `client/ArmorStandSwap`) and a right click with an empty main hand sends `SwapArmorPayload`, which swaps the four armor slots with the stand's, each slot on its own: a piece with Curse of Binding stays on (outside Creative), and the stand's `DisabledSlots` are read as `ArmorStand.swapItem` does (`ArmorStandMixin`). On a server without the mod, the click stays vanilla. Sneaking, the same click goes through `tweaks/ArmorStandPoses`, whose current pose is read from the stand itself.
- **Woodcutter** (`woodcutter/`): a `StonecutterBlock` and `StonecutterMenu` subclass with their own block, item and menu type (the stonecutter's screen is reused with a wood-toned background, recipe buttons and scroller from `tools/container_panels.py`). Its recipes are `minecraft:stonecutting` recipes with a plank as input in `data/cassonade/recipe/woodcutter`, written by `tools/woodcutter_recipes.py`; `StonecutterMenuMixin` (both sides) offers a plank only to the woodcutter and everything else only to the stonecutter. It also remembers, on the server, the piece picked while the menu is open and selects it again for the next stack, or the piece with the same last word in its name for another material; the client resets its selection by itself, so the remote data slot is cleared to send the index again. `LoomMenuMixin` does the same with the banner pattern. The block textures are the stonecutter's recoloured by `tools/woodcutter_textures.py`.
- **Dyed blocks**: `CauldronInteractionsMixin` registers, through `CauldronDispatcherAccessor`, a water-cauldron interaction for every dyed wool, carpet, bed, terracotta, glass and glass pane. It washes the whole held stack for one level of water.
- **Armor stand arms**: a stand placed from the item gets its arms (`ArmorStandItemMixin`), as in Bedrock Edition; shears on a stand with arms take them off, drop what its hands held and wear by one use, and two sticks on a stand without arms put them back (`ArmorStandMixin`). Stands summoned or loaded keep their own `ShowArms`. Server side.

### Combat

Everything shows only to a player wearing a sculk compass. Only the server knows what a mob targets: it sends that player, every 2 ticks when it changes, the list of mobs chasing them within 64 blocks (a ghast's reach), from scratch each time the compass is worn again. The same list puts the hunters on the minimap, as red dots kept on its edge when out of range; a mob too far for the client to know where it is (past its tracking range) is left out. On a server without the mod, only the bars of hurt mobs show, with no "!", eye or dots. Health bars show up to 32 blocks away, as far as the list goes for the mobs chasing the player, only for mobs in sight, and stay 5 seconds after the last hit. The sprites are generated by `tools/combat_textures.py`.

The other players show on the minimap as far as the client knows of them (its entity tracking range), spectators and invisible players left out, as vanilla's blue map marker turned the way they look, with their name. Client only: it works on any server.

### Spyglasses

- The naturalist's spyglass zooms like the vanilla one, scope and slower aim included: `PlayerScopingMixin` makes `isScoping()` true while it is used, as the game only knows its own spyglass. The server never asks, so only what the client draws changes.
- Through either spyglass, the scroll wheel picks one of three zooms, the game's (a field of view scaled by 0.1) between 0.05 and 0.2 (`ScopeZoom`, `AbstractClientPlayerMixin`; `CameraMixin` lets the camera go below 0.1), instead of the item in hand (`MouseHandlerMixin`). Back to the game's each time the spyglass is raised.
- The scope (`textures/misc/spyglass_scope.png`, over the game's) is a round lens at the end of a dark tube, in the colors of the game's frame and glass, drawn by [tools/scope_texture.py](tools/scope_texture.py).
- The panel shows while looking through the naturalist's spyglass, for what is picked along the view up to 128 blocks, about as far as the client keeps track of animals, each mob widened by 0.3 blocks to be easier to aim at from afar. The look goes through the plants with no collision that it has nothing to read about (grass, ferns, flowers), so they hide nothing behind them; crops and beehives stop it. It reads what the client knows: a horse's attributes (speed in blocks per second is the attribute × 42.16, the jump height a fit of the game's physics), each drawn as a bar from the worst value a horse is born with to the best (speed 0.1125 to 0.3375, jump strength 0.4 to 1, 15 to 30 health; a llama's strength 1 to 5), a villager's level, a crop's `age`, and a beehive's honey and occupant count. Beehives send their occupant data to clients when the count changes (`BeehiveSyncMixin`); a vanilla client ignores it. A mob's age and a villager's trades are only on the server: the client asks every second about the mob looked at (`GlanceRequestPayload`, ignored past 128 blocks or without the naturalist's spyglass in hand) and counts the age down between answers. A villager never traded with has no trades yet, and they are not generated just to be counted.
- A chest's, barrel's or Shulker box's name, given at the anvil, shows in the same panel, through the spyglass or at arm's length; a double chest takes it from either half. Vanilla sends the client nothing of these block entities: with the mod, the server sends their name alone, never their contents (`ContainerNameSyncMixin`). On a server without the mod, it does not show.
- A playing jukebox shows its song's name in the same panel, at arm's length. The client never sees the disc: it learns the song from the level event that starts it, which `LevelEventHandlerMixin` records by position, so this works on a vanilla server too.
- With a honeycomb or an axe in hand, a copper block looked at at arm's length shows whether it is waxed: the game's own pairs of waxed and unwaxed blocks (`HoneycombItem.WAXABLES`). Client only.
- With redstone dust in hand, a wire looked at at arm's length shows its `power` state, and any other block the strongest signal its neighbors give it (`Level.getBestNeighborSignal`), worked out by the client from the block states it has. Client only.
- A note block's note is read from its `note` state (0 is F♯3, each step a semitone) in the same panel, through the spyglass or, without it, from the block under the crosshair at arm's length.

### Wandering traders

- While a wandering trader's `MerchantMenu` is open, the server sends its despawn delay every second (`TraderTimePayload`, via `MerchantMenuAccessor`). The merchant screen shows it in the info icon's tooltip, as is: vanilla pauses the delay while the trader is trading. On a server without the mod, the vanilla screen is unchanged.

### Quest journal and advancements

- The game only sends the player the advancements close to those already earned. With the mod, the server sends them all (in singleplayer, the integrated server has the mod). On a server without the mod, the list is limited to what it sends.
- The mod's own advancements (backpack, organized backpack, compass, world map, marker, clock, barometer, sculk compass) are granted by the server checking the player's equipment and markers every second, even for equipment worn before they were added. They make up the "Explorer's Gear" chapter, apart from the sculk compass's and the organized backpack's, in the ruins chapter with the deep dark. The barometer's needs the clock's, the sculk compass's the compass's.
- The game's 126 advancements and the mod's 10 are spread across the chapters in [chapters.json](src/main/resources/assets/cassonade/quests/chapters.json). Chapter titles, introductions and quest hints are in the language files (`quest.cassonade.*`); a quest without a hint shows the advancement's description.
- The choice to follow the journal and the followed quest are saved per world, in `cassonade/quests.properties`; the tracker display in `config/cassonade.properties`.
- The textures (frames, medallions, rays, button icons, journal cover) are drawn by [tools/quest_textures.py](tools/quest_textures.py).

### Filtered hopper

The filter is a real item, given back when the hopper is broken, and compares the item only, not its components. A bundle or shulker box with items in it lists the accepted items (only one level deep: the containers it holds are not opened); an empty one filters itself. The hopper's speed, redstone locking and comparator output (which ignores the filter) stay vanilla. Its textures are derived from the hopper's by [tools/filtered_hopper_textures.py](tools/filtered_hopper_textures.py).

## Textures and interface

The interface follows one art direction: plain panels of sepia wood with plum shadows and golden edges, near-black slots, tan leather for the backpack and books, cream paper for pages. Hover is a cream outline (ribbon red on paper), selection a green frame. Vanilla icons keep their shape.

**The interface atlas.** All interface textures (HUD, windows, widgets, recipe book, backpack…) live in a single image, [textures/gui.png](textures/gui.png), arranged in titled sections. Edit it in a drawing program and relaunch the game: the build cuts it back into files according to [textures/gui.json](textures/gui.json). Each texture is cropped to its visible pixels (an empty texture keeps its whole area) and surrounded by a bright pink frame with its name above: paint inside the frame. Frames, names and gaps are ignored.

- To add a texture, drop it at its place under `src/main/resources/assets`, then run `python3 tools/gui_atlas.py`. Without a new texture, the same command rearranges the image.
- To change hues all at once, `python3 tools/gui_psd.py` writes `textures/gui.psd`: the same image, its pixels sorted into layers by color family (wood, dark backgrounds, leather, paper, hover cream, selection green, gold, amethyst, red, icons, misc), plus a locked layer for the frames and names. Clip a Hue/Saturation (or Curves) adjustment to a layer, then export the flattened image as PNG, transparency kept, over `textures/gui.png`. The build does not read the PSD: regenerate it after `gui.png` changes elsewhere.

**Info icons.** Some container screens show information in a tooltip, revealed by hovering a discreet "!" icon right of the window's title, where the sort buttons sit: [InfoPanel](src/client/java/com/cassonade/client/InfoPanel.java). The icon is drawn like the sort and search buttons (`storage_info` sprites, engraved dark, white when hovered; `tools/gui_textures.py`); the tooltip is a real one, a row per line, each pairing a gold subject with a cream value, and shows nothing (no icon) when there is no row. A new screen needing container information should use it rather than draw its own text. The anvil is the exception: its cost stays where vanilla draws it, on a sunk field in the mod's style (`InfoPanel.sunk`). Every screen that uses the icon:

| Screen | Line shown | Data |
|---|---|---|
| Grindstone ([GrindstoneScreenMixin](src/client/java/com/cassonade/client/mixin/GrindstoneScreenMixin.java)) | Experience given back (a range) | Computed on the client from the items |
| Furnace, blast furnace, smoker ([AbstractFurnaceScreenMixin](src/client/java/com/cassonade/client/mixin/AbstractFurnaceScreenMixin.java)) | Cooking time, fuel remaining and stored experience, each on its own line | Menu data; fuel in waiting needs `FuelTooltip` and experience `FurnaceExperienceTooltip`, both fed by the mod's server (without it, only the burning fuel counts and no experience is shown) |
| Brewing stand ([BrewingStandScreenMixin](src/client/java/com/cassonade/client/mixin/BrewingStandScreenMixin.java)) | Time left and number of brews the fuel can still make, on separate lines | Menu data |
| Wandering trader ([WanderingTraderMerchantScreenMixin](src/client/java/com/cassonade/client/mixin/WanderingTraderMerchantScreenMixin.java)) | Time before the trader leaves | `TraderTimePayload` from the server; nothing is shown without the mod |

Update this table when a screen is added or changed. The anvil ([AnvilScreenMixin](src/client/java/com/cassonade/client/mixin/AnvilScreenMixin.java)) only lifts the "Too Expensive!" cap and restyles vanilla's cost line. The other tooltips of the mod (food, maps, storage contents, enchantments) are real item tooltips, and the crosshair's [GlancePanel](src/client/java/com/cassonade/client/spyglass/GlancePanel.java) is a HUD panel, not part of this list.

**Never run `tools/build_gui.py`** unless you mean to start over: it redraws every texture from the scripts and replaces `textures/gui.png`, wiping every hand edit made in the image. The starting colors are in [tools/gui_theme.py](tools/gui_theme.py), the shapes in [tools/gui_style.py](tools/gui_style.py) (HUD, windows, widgets), [tools/gui_textures.py](tools/gui_textures.py) (backpack, bookmark), [tools/recipe_book_textures.py](tools/recipe_book_textures.py) and [tools/enchanting_book_textures.py](tools/enchanting_book_textures.py) (isometric enchanting book). `tools/panel_textures.py` draws the HUD panels, `tools/search_field_texture.py` the storage search field, `tools/cartography_textures.py` the cartography table's map sheets.

**Other textures** are drawn by dependency-free Python scripts (`tools/*_textures.py`, with `tools/pngio.py`), colors from `tools/gui_theme.py`. The mod's icon, a lump of cassonade on a wooden panel, is drawn by [tools/icon_texture.py](tools/icon_texture.py), which also writes the website's copy. The share image (`site/assets/og.jpg`, also the repository's social preview) is [tools/og_image.html](tools/og_image.html) rendered by Chrome, as its comment explains.

**World selection.** [WorldSelectionScreen](src/client/java/com/cassonade/client/WorldSelectionScreen.java) subclasses `SelectWorldScreen`, which `GuiMixin` swaps for it whenever vanilla's exact class opens. Loading the worlds, searching, playing, editing, re-creating and deleting stay vanilla's `WorldSelectionList`: the screen only lays it out in a `FramedPanel` over the loading screens' background and draws the panel of the world selected. The list is restyled for this screen only (`WorldSelectionScreen.styles`): `AbstractSelectionListMixin` drops its background, separators and selection outline and puts the rows at the panel's edge with the scrollbar inside, `WorldSelectionListMixin` widens the rows, `WorldListEntryMixin` draws them, `AbstractScrollAreaMixin` draws the scrollbar as a sunk groove with a wooden handle; the Realms upload list stays vanilla. The time played comes from the player's statistics in the save (`players/stats`), read once per world while the screen is open. `-Ptests=WorldSelection` creates three worlds and takes screenshots, in English at 1920×1080 and in French at the smallest GUI (426×240).

## Recipes

The rebalanced recipes are generated from the vanilla jar by [tools/rebalance_recipes.py](tools/rebalance_recipes.py). Only the output amount changes: shapes, recipe book groups and unlocks stay vanilla. The same script writes the stairs and slabs → blocks and wool → string recipes in `data/cassonade/recipe/uncraft`. To adjust a number, edit the `RULES` table and run the script again:

```sh
python3 tools/rebalance_recipes.py ~/Library/Application\ Support/minecraft/versions/26.3/26.3.jar
```

## Translations

Every displayed text goes through the language files in `src/main/resources/assets/cassonade/lang/`. Keep every locale in sync: `en_us.json`, `fr_fr.json`, `es_es.json`, `pt_br.json`, `de_de.json`, `zh_cn.json`, `ru_ru.json` and `ja_jp.json` should cover the same keys. New languages are welcome: copy `en_us.json` under the game's locale code, translate the values, and preserve formatting placeholders such as `%s` and `%1$s`.

## Documentation

A change players can see updates, in the same commit:

- the [README](README.md) (the feature's section, and the tables if needed);
- the website, if the feature is shown there: [site/_data/en.yml](site/_data/en.yml) and [site/_data/fr.yml](site/_data/fr.yml), always both. Each feature has its section on the home page and a page of its own (`site/features/`, `site/fr/fonctionnalites/`), whose texts are the feature's `detail` in the same files; the page files only hold its title and description for search engines. The icons of their crafting grids are copied from the game's textures by [tools/site_recipe_icons.py](tools/site_recipe_icons.py); the blocks among them (lightning rod, sculk sensor, woodcutter), which have no flat texture, are drawn by the game itself in the screenshots test (`-PsiteScreenshots`). A recipe that fits the inventory's crafting grid shows in a 2×2 grid, the others in the crafting table's 3×3.

The [CHANGELOG](CHANGELOG.md) is never edited by hand.

## Commits

Messages follow [Conventional Commits](https://www.conventionalcommits.org/), in English: `feat(<feature>): <what the player gains>`, `fix(<feature>): <what is fixed>`. The scope is the feature: `backpack`, `compass`, `world-map`, `clock`, `inventory`, `farming`, `elytra`, `hopper`, `quests`, `combat`, `spyglass`, `recipes`, `tweaks`, `interface`. Website changes are `docs(site): …`.

The message describes the result for the player, not the implementation: `feat(hopper): give every hopper a filter slot`. [git-cliff](https://git-cliff.org) writes the CHANGELOG from them (settings in [cliff.toml](cliff.toml)); only `feat`, `fix` and `perf` appear in it.

## Releasing

The version lives in `gradle.properties` and is only changed by the release workflow, started by hand from GitHub: Actions tab → Release → Run workflow, choosing the version type:

| Choice | Effect |
|---|---|
| `alpha`, `beta` | next pre-release: 0.1.0-alpha.1 → 0.1.0-alpha.2, then → 0.1.0-beta.1 |
| `release` | final version of a pre-release: 0.1.0-beta.2 → 0.1.0 |
| `patch`, `minor`, `major` | 0.1.0 → 0.1.1, 0.2.0, 1.0.0 |

The workflow ([release.yml](.github/workflows/release.yml)) updates the version, adds the CHANGELOG entry, builds the mod, commits both files, tags `v<version>` and publishes the jars in a GitHub release, with the CHANGELOG entry as notes; a pre-release is marked as such. The jar is then uploaded to Modrinth and CurseForge, each once its project id is set as a repository variable (`MODRINTH_ID`, `CURSEFORGE_ID`) with its token as a secret (`MODRINTH_TOKEN`, `CURSEFORGE_TOKEN`). The version is computed in [tools/next-version.sh](tools/next-version.sh). Never tag by hand. To preview the entry that will be added: `git cliff --unreleased` (install git-cliff with `brew install git-cliff`).

Every push to `main` and every pull request also build the mod ([build.yml](.github/workflows/build.yml)); the jar can be downloaded from the Actions tab.

## Website

The mod's website is in [site/](site/), a Jekyll site published on GitHub Pages on every push to `main` that changes it ([pages.yml](.github/workflows/pages.yml)). One page in English (`/`) and French (`/fr/`): the text is in [site/_data/en.yml](site/_data/en.yml) and [site/_data/fr.yml](site/_data/fr.yml), the layout in [site/_layouts/home.html](site/_layouts/home.html), shared facts and store links in [site/_data/mod.yml](site/_data/mod.yml). To preview it locally, with Ruby and the `jekyll`, `jekyll-seo-tag`, `jekyll-sitemap`, `jekyll-github-metadata` and `webrick` gems installed: `jekyll serve` in `site/`.
