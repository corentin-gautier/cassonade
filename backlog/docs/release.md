## Commits

- English Conventional Commits: `feat(<feature>): <player benefit>`, `fix(<feature>): <what is fixed>`. Describe the player-facing result, not the implementation.
- Only `feat`, `fix`, `perf` reach the changelog.
- Scope = the feature as the README and site name it: `backpack`, `inventory`, `hopper`, `minimap`, `world-map`, `clock`, `waystone`, `spyglass`, `elytra`, `quests`, `combat`, `sculk-torch`, `harvest`, `woodcutter`, `recipes`, `lights`, `sea`, `ambience`, `villages`, `structures`, `interface`, `tweaks`. Site: `docs(site): …`.
- `CHANGELOG.md` is generated by git-cliff (`cliff.toml`): never edit it.

## Releasing

- Never edit the version in `gradle.properties` or create tags by hand.
- GitHub › Actions › Release › Run workflow, with a version type:

| Choice | Effect |
| --- | --- |
| `alpha`, `beta` | Next pre-release |
| `release` | Final version of a pre-release |
| `patch`, `minor`, `major` | Usual bump |

- `release.yml`: bumps the version, writes the changelog entry, builds, commits, tags `v<version>`, publishes a GitHub release, then uploads to Modrinth and CurseForge (once their project ids are set as repository variables).

## Workflows

| Workflow | Trigger | Does |
| --- | --- | --- |
| `build.yml` | Push to `main`, pull requests | Builds the jar |
| `release.yml` | Manual | Release, see above |
| `store.yml` | Push changing `promo/store/` | Syncs the Modrinth page and gallery (`tools/modrinth_sync.py`) |
| `pages.yml` | Push to `main` changing the site | Publishes `promo/site/` to GitHub Pages |

CurseForge page: synced locally with `tools/curseforge_sync.py` (`open`, `text`, `gallery`, `check`, `close`); commands in CONTRIBUTING.md, "Releasing".

## Website

- `promo/site/`: Jekyll, English (`/`) and French (`/fr/`). Texts in `_data/en.yml` and `_data/fr.yml`, always both; feature pages hold only title and description.
- The home page reads as one Minecraft day: each section has an hour that drives the sky behind the page.
- HTML and CSS first, no framework or dependency, works without JavaScript, AVIF screenshots, lazy images.
- Preview: `jekyll serve` in `promo/site/` (gems listed in CONTRIBUTING.md, "Website").

## Videos

- `promo/video/`, ignored by git: one folder per film (`overview/`, `ambience/`), shared `music/`, `icons/`, `fonts/`. Its own README describes it.
