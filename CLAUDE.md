# Cassonade

Fabric mod for Minecraft 26.3 (Java 25, Gradle, Fabric API). The [README](README.md), written in English for players, describes every feature and is the reference for expected behavior. Technical details (internals, textures, recipes, tests, releases) are in [CONTRIBUTING.md](CONTRIBUTING.md).

## Mod Philosophy

The mod fixes small annoyances without changing how the game is played. Before adding anything:

- No new ores, equipment tiers, magic, machines, monsters, biomes, or dimensions. Nothing that makes the game easier to complete—only more pleasant to play.
- A feature is unlocked by equipping a vanilla item (compass, clock) or an item crafted from vanilla items (backpack, world map). Vanilla progression must not change.
- The interface keeps Minecraft's pixel style and sounds, following the mod's art direction (sepia wood, dark slots, leather, cream-colored paper).
- Keep the interface consistent everywhere, with no configurable options: this is what distinguishes the mod from a modpack of dozens of mods with disparate styles and scattered settings. Every feature should work in one way, as close to vanilla as possible; do not add screens or configuration options.
- The client must remain usable on a server without the mod: features that require the server should fall back to vanilla behavior.

## Commands

- `./gradlew build`: the jar is written to `build/libs/`.
- `./gradlew runClient`: launches the game (username `Corentin`, offline mode, worlds in `run/`).
- `./gradlew runClientGameTest`: runs end-to-end tests in the actual client; screenshots are saved at 1920×1080 in `build/run/clientGameTest/screenshots/`. Run this after changing behavior or the interface.
  - `-Ptests=Gear,Quest` runs only the specified tests (class name without `ClientGameTest`: `Gear`, `WorldMap`, `Storage`, `Hopper`, `Everyday`, `Screens`, `Quest`, `Interface`, `Clock`, `Tweaks`, `ArmorStand`, `Lights`, `Anvil`, `Bookshelf`, `Cauldron`, `Woodcutter`, `Loom`, `FlowerPot`, `VehicleExit`, `SignEdit`, `Combat`, `Markers`, `Inventory`, `Search`, `Tooltips`, `Workstations`, `InfoPanels`, `WorldSelection`, `Spyglass`, `Glance`, `DedicatedServer`, `VanillaServer`). Run only the tests relevant to the change; while developing a feature, prefer a small dedicated test (such as `Clock`), and split a test that grows to cover several features.
  - `-PsiteScreenshots` reuses the site's screenshots (see `site/assets/screenshots/README.md`).

## Organization

- `src/main`: shared client and server code (items, slots, recipes, network payloads, server mixins). Each feature has its own package (`gear`, `compass`, `hopper`, `combat`, etc.) and is registered through an `init()` method called from `Cassonade`.
- `src/client`: rendering and screens (HUD, minimap, map, journal); entry point `CassonadeClient`.
- `src/gametest`: automated client tests.
- Mixins are declared in `cassonade.mixins.json` (main) and `cassonade.client.mixins.json` (client).
- `src/main/resources/data/minecraft/recipe`: rebalanced recipes, generated by `tools/rebalance_recipes.py`; do not edit them by hand.
- All displayed text goes through language files: update `en_us.json` and `fr_fr.json` together.

## Textures

- **Never run `tools/build_gui.py`**: it redraws `textures/gui.png` and erases manual edits.
- All interface textures live in the `textures/gui.png` atlas (layout in `textures/gui.json`), which Gradle splits during the build. To add a texture, place it under `src/main/resources/assets/…`, then run `python3 tools/gui_atlas.py`.
- Other textures are drawn by dependency-free Python scripts (`tools/*_textures.py`, `tools/icon_texture.py`, using `tools/pngio.py`). Colors come from `tools/gui_theme.py`.

## Code

- Use tabs for indentation. Write comments in English to explain why, matching the density of nearby code.
- Follow the style of the file being changed rather than introducing new patterns.

## Documentation

Any change to player-visible behavior must update the following in the same commit:

- the [README](README.md) (the feature section and tables, if applicable);
- [CONTRIBUTING.md](CONTRIBUTING.md), if the documented internals change;
- the site, if it covers the feature: update both [site/_data/en.yml](site/_data/en.yml) and [site/_data/fr.yml](site/_data/fr.yml). Each feature has a section on the home page and its own page (`detail`, with more information and an FAQ); files in `site/features/` and `site/fr/fonctionnalites/` contain only the title and description. If it doesn't yet cover the feature, ask if it should be added.

Never edit the [CHANGELOG](CHANGELOG.md) by hand: git-cliff generates it from commits at release time.

## Commits and Versions

- Commit messages must be in English and follow [Conventional Commits](https://www.conventionalcommits.org/): `feat(<feature>): <player benefit>`, `fix(<feature>): <what is fixed>`. `perf` is also included in the changelog; other types (`refactor`, `docs`, `chore`, `ci`, `build`, `test`) are not.
- Use the affected feature as the scope: `backpack`, `compass`, `world-map`, `clock`, `inventory`, `farming`, `elytra`, `hopper`, `quests`, `combat`, `spyglass`, `recipes`, `tweaks`, `interface`. Site changes use `docs(site): …` and are excluded from the changelog.
- Describe the player-facing result, not the implementation: `feat(hopper): give every hopper a filter slot`.
- The version is in `gradle.properties` and is changed only by the release workflow, launched manually from the Actions tab (Release → Run workflow: `alpha`, `beta`, `release`, `patch`, `minor`, `major`). It writes the CHANGELOG entry with git-cliff ([cliff.toml](cliff.toml)), commits, tags `v<version>`, and publishes the jars to GitHub, then to Modrinth and CurseForge once their project IDs are configured (variables `MODRINTH_ID`, `CURSEFORGE_ID`; secrets `MODRINTH_TOKEN`, `CURSEFORGE_TOKEN`). Do not create tags manually.
